# Native-home handoff audit, 18 November 2026

Scope: diagnostic build `122430224fb8ea95a7669f987087eda72ce43e77`, second
user recording, and candidate source base `16be3ea`. This is a source/evidence
audit, not a device-verified fix. No fixed pixel correction is justified.

## Located failure boundary

The reported Back-to-home jump is at the native handoff, not ordinary blur:

| Relative seconds | Event |
| --- | --- |
| 12.510 | Back preview selects an actual native screenshot, no fallback |
| 12.582 | Gesture invoked |
| 12.602 | History navigation 5 starts |
| 12.683 | Common completion helper; screenshot transform is nonidentity |
| 12.703 | Navigation commits |
| 12.780 | Browser receives document-paint signal |
| 12.921 | Animator waits for native content shown |
| 13.040 | Native-content-shown callback |
| 13.041 | Animator finished |

No ordinary blur layer starts for this return. Changing its hold duration cannot
repair this specific native handoff. The paint event is not the native view's
presented frame. Native-content-shown and animation-finished correlate with the
reported symptom, but do not identify which layout owner moved.

## Compared against pinned Chromium

* `NativePageBitmapCapturer` retains upstream capture translation:
  `-nativeOverlap + (fullscreen ? topControlsHeight : 0)`.
* Sandium synchronous native blur/fallback children subtract top-controls height,
  compensating that fullscreen capture contract. No evidence warrants adding a
  fixed status-bar offset here.
* Upstream `OnInvokeAnimationDisplayed` waits for native content for an embedder
  screenshot. `OnContentForNavigationEntryShown` finishes the animator. Sandium
  retains this lifecycle, with numerical observations added.
* `apply-sandium-back-controls.py` already restores upstream gesture-start
  controls reveal ordering. Its remaining behavior change avoids waiting for
  disabled-feed restoration, preserving the native delegate's fade/lifecycle.
* The substantive home-layout delta is the wallpaper outer FrameLayout in
  `homepage-surround/backing.json`: `getView()` returns the wrapper, while
  `NewTabPage.updateMargins()` targets the inner foreground. Capturing the
  wrapper includes wallpaper, and the smooth-transition delegate targets it.
  The corresponding live inner-margin and outer-origin values are not logged
  at the failed handoff. This is the next ownership contract to verify, not
  evidence that the wrapper itself must be removed.

## What the existing geometry does and does not prove

Outgoing home reports window Y=-48px, attached. The renderer container reports
Y=0 but is detached. Comparing these as two simultaneous on-screen origins is
invalid. Screenshot/compositor local positions are zero; this is not their
composed window position. The screenshot becomes nonidentity-transformed during
Back, but its matrix is not exported. Restored native-view geometry is absent.
Consequently neither 48px nor the previously observed 112px can be used as a
safe correction. There are no populated CONTROLS/BACK_HANDOFF events to establish
browser-control offset or viewport resizing at this boundary.

## Next minimal evidence

the same scene before and after reveal, including hidden address bar and cancelled
Back. Do not position against a detached renderer container or introduce another
timing delay to conceal mismatched geometry.

## Follow-up: exact native reveal owner

Retrieved `chrome/android/java/src/org/chromium/chrome/browser/ntp/NtpSmoothTransitionDelegate.java`
directly from Chromium revision `d331de35ca8ab1358c7a17e4bd41627d55eaef51`.
SHA256: `e03a926af7ce8e884c98496e8669b600cf37c2b442f050c48f19ca49485bd8f5`.
Its `prepare()` sets the view alpha to zero. `start()` observes feed restoration
then animates alpha to one over 100ms. Completion invokes the supplied callback;
there is no translation, margin, resize or scroll operation in that delegate.
The source therefore supports a screenshot-to-live mismatch investigation, not
a claim that this delegate itself moves the homepage.

The wallpaper owner initializes before attachment, adds wallpaper and foreground
as MATCH_PARENT siblings, and redirects only NTP margin updates to foreground.
The existing NTP attachment callback still invokes `updateMargins()`. Wallpaper
readiness callbacks change backgrounds and invalidate paint; they do not explicitly
change margins or translation. Source inspection did not establish a duplicate
margin application or a delayed layout callback specific to the failed return.

### Bounded diagnostic design, not yet implemented

Arm an optional observer from `NewTabPage.enableSmoothTransition()` only while
the existing regular-profile recorder session is active. Sample up to 16 native
pre-draw frames or 500ms, whichever comes first, without requesting frames/layout.
Record outer root and foreground origins, sizes, top/bottom margins, translation,
alpha, attached state, plus browser-controls content/height/offset values. Stop on
session change, cancellation, detach or timeout. Include the actual start/end
native reveal callbacks so samples can be aligned to the screenshot teardown.
Use a dedicated schema event instead of repurposing reserved fields. Preserve
profile and epoch gates, bounded buffer, no URLs/text, and no private capture.
This requires recorder schema + Java target/dependency/reset ownership integration;
it should not be slipped in as an untested source-only probe. A third video without
these restored-view values would not resolve the current coordinate ambiguity.
