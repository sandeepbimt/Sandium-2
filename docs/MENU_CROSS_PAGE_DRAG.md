# Cross-page editor drag and saved-order directory

User screenshot155650 shows editor page2 active; static image alone cannot prove the event failure. Source analysis found that hover paging rebuilt the complete menu while Android's drag session depended on child listeners. Replacement tiles never received the initial DRAG_STARTED. The old hover also acted only on ENTERED, with a650ms cooldown and no sustained-hover timer.

The stable sheet now owns its own local drag token from start through end. It checks visible target bounds in shared root-view coordinates (including nonzero popup origins) at drop, so replacement tiles remain valid targets. It does not activate an action.450ms dwelling over another page indicator or a32dp viewport edge changes page; RTL direction is respected. Exit/drop/detach cancels delayed hover. Invalid drops never change order. Page-slide animation and popup resize are suppressed during drag to keep target geometry stable; normal presentation resumes after ending. Existing tap-to-move accessibility commands remain available. No new browser/network operation is introduced.

Persistence audit: Done serializes draft into sandium.menu.layout.v1 / layout via SharedPreferences.apply; constructor loads the same storage. Cancel/Back intentionally discard unsaved draft. The All menu directory previously ignored this saved order and iterated catalog order, appearing reset. It now iterates saved knownKeys filtered by live availability. Conditional unavailable items remain remembered, not made executable. Existing menu preferences store action IDs/order only, not site URLs or private page content. This does not change private per-site storage semantics, which need separate owner audit.
