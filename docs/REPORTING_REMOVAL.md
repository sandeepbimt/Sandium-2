```

```

Effective GN must contain `enable_brave_stats_updater=false`. Do not infer that setting from this source transform. Validate generated target sources and final APK/native link inputs before marking removed.

## What changes

- Daily usage updater `.cc/.h` is already behind its GN flag. This patch also gates its exclusively used parameter implementation and removes Android restart call/JNI declaration/native callback together. Safe Browsing API key JNI remains.
- P3A's reporting static-library source list is replaced with metric enum conversion and compatibility headers/preferences only. It no longer compiles uploader, scheduler, message/config/measurement stores, constellation crypto or component installer. The actual service and histogram-observer instances and startup/component-registration calls are removed. Remaining `P3AService` header is an inert compatibility surface for legacy preferences and independently compiled SERP helper declarations, not the original service. No instance is created. It cannot upload, observe, schedule or fetch configuration.
- P3A utility/local feature counters may remain in other components; those are not the removed reporting service. Their removal is distinct from maintaining Shields local counts. Historical preference keys are retained for safe upgrade and do not revive the absent service. Old reporting storage is not deleted.
- Android's original `MinidumpUploader.java` and concrete HTTP factory are excluded from the shipping GN source list. The replacement class retains only error-result/API compatibility and no networking or file I/O. Brave's HTTP factory source additions are empty. Chrome's scheduling, direct intent upload and explicit upload-by-local-ID implementations are removed. An already-queued upload job finishes without upload, file access, deletion or rescheduling.
- Local crash capture, Android/logcat evidence, native safety assertions and local crash metrics remain. This does not disable Chromium crash handling globally or modify OS/network permissions. The native non-official upload URL is already empty on this build; Android's separately hardcoded upload implementation is the path removed here.

## Replay/reset paths

Machine-readable inventory: `.circleci/scripts/reporting-removal-paths.json`. The generated uploader is overwritten on every apply (including replay) and must not be passed to git restore. Preservation validation fails before writing the usage cluster; each other phase also validates its own inputs before writing. This is per-phase atomic validation, not a transaction spanning every phase or filesystem failures.

Before existing source transforms replay, restore the usage files and all paths in `P3A_FILES` from the pinned core. Also restore core `components/minidump_uploader/sources.gni`, Chromium `components/minidump_uploader/BUILD.gn`, `chrome/android/java/src/org/chromium/chrome/browser/crash/MinidumpUploadServiceImpl.java` and `ChromeMinidumpUploadJobServiceImpl.java`. The new core `components/minidump_uploader/android/java/src/org/chromium/components/minidump_uploader/MinidumpUploader.java` is generated by this patch. Do not restore shared files after all feature patches have been applied.

Surgical Java activity patch composes with removal of unrelated features, provided their transforms do not replace the entire file afterward. Coordinate P3A browser-process/shared GN edits with other component workers.
