**Scope.** Opt-in local source overlay. No changes to the base recipe, CI, fallbacks, UI, checkpoints or user data. Plain checkout/build of the parent recipe does not activate this candidate. Importing the Git commit alone is not an APK upgrade. No use of uBlock Origin as an extension. List dialect markers such as `ext_ublock` in the upstream preprocessor describe filter syntax, not an installed extension.

## Source map / what is actually implemented

* `.circleci/scripts/apply-sandium-filter-subscriptions.py` **at the reference**, not imported as CI: `FILTERS` is the authoritative ordered sequence. `compose.py` rejects any URL or title drift. `catalog.json` lists all 30, including the direct annoyance leaf and the exact EasyList URL; no extra upstream component catalog. All 30 create enabled in #1442. None of these 30 is factory-off. Users can disable/delete later; arbitrary custom subscriptions are a separate feature, not another fixed inventory. The four historic AdGuard IDs 20,21,19,22 had a one-off transition in Sandium's older profiles, not a recurring override. RawS #1462 has no such subscription state; this port uses a new directory, not a migrator for independent Brave profiles.
* `.circleci/scripts/apply-sandium-filter-bootstrap.py` plus pinned Brave `ad_block_subscription_service_manager.{cc,h}`: profile startup, enabled-only repair/refresh, immediate creation downloads, first timed check after 60 s, hourly scan, retry after failed attempt, list expiry/fallback 168 h, bounded expiry (336 h). `subscription_service.h` implements credential-free HTTPS, private-profile exclusion, atomic cache writes, tombstone/disabled states, manual refresh and native choices. No Android UI imported. It keeps reference URL identity; no proxy substitution. Redirects must retain the same HTTPS origin (including effective port), with no URL credentials or new data. Cross-origin mirrors fail closed at refresh and keep the previous cache. New cache writes require a nonempty parser result after native preprocessing; malformed/zero-rule responses never replace last-known-good bytes. A positive parser count is not a cryptographic authenticity check. RawS imposes limits (three downloads concurrently, 45 s timeout, the Chromium bounded-string 5 MiB limit per feed, 96 MiB per generation); failure is logged and cached valid files are retained. These limits and real responses need validation. Profile/setup, fetch and filesystem code not executed on Android.
* `ad-redirects/ad_resources.py`: additional-engine, permission-zero `||ohjpfawpaap.in^$third-party,script,subdocument,image`. Clear distinction between first-party media and matched ad resources. No #1442 serialized DAT reused or retired; RawS uses its own live Rust engines and versioned list body cache.
* `filter-compat/{subscriptions,modifier,denyallow,token_index,popup_matcher}.py`: the compositor reuses pinned conditional-line helper (including the #1442 span-copy fix) and Rust patch edits for redirect modifiers, plain scoped destinations, token index and explicit `$popup`/`~document` types. It applies only the Rust portion of popup_matcher; `policy.h` implements the reference primary/additional/exception/important merge. Redirect-modifier parsing does **not** add resource substitutions or normal-request URL rewrites at the browser boundary.
* `ad-redirects/popup.py`: the source helper is used verbatim except for the Brave-only Shields/redirect pref reads. Veto only after Chromium allows a normal new window and only for the recorded auction signature or a cross-site embedded exchange route with `/10/<32 hex>` plus numeric `psid`. No blocking based on video alone, URL fragments, any popup, or a `psid` key alone. Native popup ALLOW bypass remains. Global enabled mode only; no Brave per-site policy/UI.
* `ad-redirects/media_popup.py` and `filter-compat/popup_navigation.{py,cc.inc}`: carry issuer provenance through the pinned Blink/IPC hooks; scripted new windows/untrusted synthetic links only for the rule throttle, no forms. Consume new-tab provenance once; initial `about:blank` is not consumed, browser-initiated navigation retires it. 10 s provenance lifetime, 100 ms **total held time**, start+redirect checks, timeout/late reply fail-open, recheck settings before cancellation. Original Chromium user activation, navigation and media callbacks remain in control.
* Network path: expand the existing document factory to XHR, media and ping, in addition to existing types; no POST or privileged request widening. Separate child-frame-only, bounded throttle consults the Rust engine before `BLOCK_REQUEST_AND_COLLAPSE` for a positive subdocument match. Only HTTP(S), renderer-initiated, matching non-opaque parent initiator. A definitely blocked image sets Chromium's `should_collapse_initiator` bit; ordinary failures do not.
* Cosmetics: actual Rust `url_cosmetic_resources`, scoped `hide_selectors` and exceptions, restricted declaration builder, same-document identity checks, Android-only ChromeRenderFrame IPC and Blink user stylesheet. No DOM-wide polling, empty-element heuristic, arbitrary CSS declarations or executable remote scripts. Simple new matching elements are covered by CSS without repeating the browser request. **Not implemented:** generic class/ID discovery, procedural actions, CSS style directives, scriptlet execution, complete trusted redirect resources or CNAME uncloaking. Standard scoped hiding, bounded selectors and this two-engine merge are not full Brave cosmetics.
* Startup: keep #1462's packaged rules, add the player rule before publishing the first snapshot. Prewarm the offline engine at profile startup without holding any navigation. Requests arriving before readiness pass through; a factory installed during prewarm can protect later eligible requests once ready. Thirty remote lists are NOT guaranteed on a fresh offline profile. Full-list refresh constructs a replacement snapshot on a separate sequence, while the previous complete snapshot continues handling requests. A failed or superseded generation does not replace it. Match latency and transient memory still need device measurement under refresh. A green test must not hide a slow-path leak.

## Verification on this handoff

Run `CXX=g++ python3 raws-adblock/port1442/tests/test_port.py` and repeat with `CXX=clang++`. Requires Python 3, either C++20 compiler and, for the real layout test, Playwright Python with system Chromium. The test reads #1462's original `raws-adblock/native/document_subresource_factory.cc` and verifies its exact Git blob. Test doubles are called out in test source. Desktop Chromium layout tests inject the generated CSS directly, not through the proposed Android Mojo endpoint.

`smoke1442.cc` is a separate true CXX/Rust target: six network expectations, four popup expectations, a URL-specific hide plus exception. **Not built/run here.**

## Offline source composition on the prepared build host

1. In a clean clone containing the verified parent, import the prerequisite bundle (see outer handoff). Keep #1462 checked out separately; use the new local worktree for this port. The git object for #1442 must also be available in this repository, even though it is on a separate history/branch.
2. Prepare an independent **disposable copy** of the reviewed #1462 Chromium source postimages, including its `src/brave` native dependency subset. It must have the exact Chromium Git HEAD listed above, base offline assets and preimages matching #1462's production recipe. A clean stock Chromium source tree alone is not such a copy. Supply a separate local Brave Core Git checkout at the RawS pin for source identification. No restore, download or staging of a checkpoint is performed by this tool.
3. Produce a delta in a **new directory outside all inputs**. This step is local and read-only with respect to all source inputs:

```sh
python3 raws-adblock/port1442/compose.py "$RAWS_PORT_WORKTREE" "$DISPOSABLE_1462_SRC" "$BRAVE_CORE_CHECKOUT" "$NEW_DELTA_DIR"
```

The composer verifies the catalogue, original Git blob IDs of the #1442 transforms, Chromium native/renderer sources, and #1462 active file postimages. It must stop on any mismatched source; do not remove checks. `delta-receipt.json` lists before/after SHA-256 for each output. On the prepared host, review the receipt and apply the **generated** files only to the disposable source copy, not a baseline or checkpoint. New code remains unadmitted by the existing protected CI recipe. Independently generate GN for a local Release ARM64 build and run standard GN dependency checks and the target `//components/sandium_adblock:host_smoke1442` before considering an APK.
