# Conservative first-target capacity boundary

The first Full-U run starts fresh. Old 1402 compressed ratios are not compatible target measurements. Actual accepted Full-U archive/save timings are recorded and can increase future time reservations.

Disk admission currently reserves 105% of workspace bytes plus 9 GiB for capture, and a further 8 GiB for work. This may stop a large compile on the current machine. Such a stop is a resource HOLD after preserving a verified checkpoint, not permission to retry five identical stages indefinitely.

A previous compressed archive size plus net workspace growth is not a safe replacement bound: unchanged-size files can be rewritten with higher entropy. A future tighter estimator must bound all changed/new file bytes against a verified same-scope manifest (or use explicitly provisioned larger storage), not infer compression from net growth alone. No full-build capacity guarantee is made before measured target workspaces exist.
